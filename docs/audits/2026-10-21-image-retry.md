# 画像1件の障害と再試行

2026-10-21。実アプリ/AssetImage/VisualChoices/有料画像取得処理に模擬認証・利用権を接続してローカル実ブラウザで確認。本人のGoogle認証/契約/Firestore/Stripeには接続していない。

| 操作 | 確認結果 |
|---|---|
| 令和7年下期・問48の選択肢画像だけHTTP503 | その画像の場所にエラーと「画像を再試行」。本文と別の図は維持 |
| 503継続中に再試行 | 再取得して同じ案内へ戻る。年度/問48を維持 |
| 障害中に原本を開く | 原本ページを取得・復号して表示。選択肢画像と独立 |
| 復旧後に実ボタンで再試行 | 問題全体の再読込なしで選択肢画像を再取得・復号、エラー解消 |
| HTTP200で破損したWebPデータ | img復号エラーを検知し案内。復旧/再試行で再取得し正常表示 |
| ブックマーク後に503で再読込/復旧 | 問48・ブックマークの表示を維持し画像を再表示 |

対象画像への実通信7回、障害応答4回（503/破損）、正常応答3回。利用権拒否0、模擬失効なし。実測値は `2026-10-21-image-retry.json`。別担当がコード/差分を読取レビューし、実サービスへの接続や既存期限検証を壊す問題なし。

`node tests/private-images.test.mjs`、構文確認、明示フラグなしでは待受しないことも成功。アプリ本体/公開設定は変更せず、デプロイ不要。

## 再現

生成済み教材がない場合だけ `npm run test:private-staging` で準備する。

```sh
node scripts/serve-private-expiry-check.mjs --serve-local-check --image-failure-check
```

`http://127.0.0.1:5207/` を開く。専用ポートの端末記録だけを初期化して有料問48を表示。初期状態は選択肢画像だけ503。「画像通信を復旧」→アプリの「画像を再試行」で復旧。「破損画像を再現」で破損応答へ切り替える。障害切替は再読込する。終了時にサーバーを停止する。

## 範囲外

- ローカル実ブラウザ確認であり、本人スマホ/Android/実回線の確認ではない。
- 障害注入は配信ハンドラー手前の模擬応答。401/403・失効後拒否・実IDトークン検証の証跡に含めない。
- fallback両方失敗、原本ページだけ失敗、再試行中の画面変更との競合は未実施。
- 本人の記録やクラウド記録を上書きする手順ではない。模擬認証/保存/決済を本番に反映しない。
