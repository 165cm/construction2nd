# 実ログイン・既存配備APIの読取確認

2026-10-24。本人が使うGoogleログインで、既存配備のbillingAccessと教材APIの認証境界をまとめて確認するローカル画面を準備。新600円の未配備createCheckoutを実行する試験とは分ける。

## 実行方法・本人操作

起動（外部配備なし）：

```sh
node scripts/serve-auth-readonly-check.mjs --serve-read-only-check
```

このMacのChrome等で http://localhost:5214/ を開く。127.0.0.1ではなくlocalhostを使う。Firebaseの既存設定を読取し、localhostは許可済み/127.0.0.1は未許可であることを確認した。許可ドメインの追加/変更は行っていない。

1. 「購入済みのテスト用アカウント」を選び、Googleでログインして一括確認する。以前このアプリでテストした本人アカウントを使う。
2. 完了後はこの確認画面からログアウトし、「以前テストした未購入アカウント」を選んで同じ確認を行う。
3. 異なる2アカウントの両方の完了表示を確認する。エラーは合格とせず、アカウントの選択と現在の利用権の期限を確認する。トークンやパスワードをチャットへ貼らない。

確認項目は、未ログインのCallable拒否、未認証/不正token/UID指定だけの教材拒否、有効ログインのbillingAccess、data.uidに架空の別UIDを指定しても同じ本人結果、本人の権利に応じた教材200/403、教材の年度/50問/利用期限/キャッシュ禁止。2アカウントのUIDは画面のメモリ内で区別し、結果には保存しない。別UID指定は固定の架空文字列であり、全ての別ユーザーIDについて総当たりする試験ではない。

## 安全の境界

- 初期値では未起動。厳密な明示フラグだけでVite/HTTPを読み込み、127.0.0.1だけへ待受する。ブラウザのHostはlocalhost:5214へ限定。
- Firebase Webの公開設定4項目だけをVITE_FIREBASE_から取り込む。サービスアカウント/Stripeキーは取得・埋込しない。projectIdはconstruction2nd固定。
- Googleログインは専用の名前付きapp/inMemoryPersistence。学習アプリ側の保存領域や既存ログイン状態へ操作しない。SDKのログインに伴う通常の認証サービスの記録まで「一切の外部書込なし」とは表現しない。
- 呼び出すCallableはbillingAccessだけ。Checkout/Portal/Firestore書込/返金/契約操作のUIや処理はない。
- 教材プロキシはOrigin・nonce・POST・固定GET先・r7_2だけに制限。Bearerはサーバーのメモリを通過し、送信先は自サービスの教材APIだけ。トークン/教材本文をログ/ファイル/結果へ保存しない。取得したJSONは問題数/年度/期限だけを返し、教材本文はブラウザへ転送しない。
- 秘密設定ファイル/API等の別経路を拒否。任意の転送先やUIDを受け取らない。未認証・未購入応答の本文も返さず破棄。
