# 決済記録の分類と保存準備

2026-10-22。本人回答は「申告方法はまだ未定・分からない」。個人事業/雑所得/法人、青色/白色、消費税やインボイスの扱いを推測で確定しない。以下は記録の整理と手順案であり、申告方式・保存年数・会計方法の採用、データ取得/削除の実行ではない。

## 保存を分ける理由

| 種類 | 例・目的 | 保存期間の扱い |
|---|---|---|
| 税務・会計の原資料 | 請求書/領収書等の電子取引データ、売上・返金・手数料・Stripe入金明細、銀行入金との照合に必要な資料 | 申告区分・所得区分・書類の種類・消費税等の適用と起算日を確認して決定。アプリの利用期限や学習記録削除と連動して消さない |
| 利用権と支払いの対応 | 顧客/決済/請求書/契約ID、プラン、開始/終了、返金による失効 | 提供・請求・再処理/返金対応に必要な期間を別に設計。Firestore全体を税務書類として一律長期保存しない |
| 購入予約 | 試行ID、作成/終了予定、プラン、未完了Checkoutとの対応 | 終了時刻だけで削除しない。遅延決済や通知未着との整合を確認して期限設計 |
| 返金・紛争対応 | 対象支払い、返金処理の結果、必要な対応記録 | 通常問い合わせの完了後最長1年とは区別。対応中/法令上必要な記録の範囲と期間を確認 |
| 学習記録 | 学習状況、設定、模試履歴 | 税務保存とは別。本人確認後30日以内目標の削除受付と6か月ごとの必要性点検の決定済み方針に従う |
| 通常問い合わせ | 操作質問等の履歴 | 対応完了後最長1年、不要なら早期削除。未解決の請求/紛争等は別扱い |

実装の `billingCustomers` / `sandboxBillingCustomers`、利用権、失効マーカーは動作制御用の情報で、帳簿・原資料一式の代わりにはならない。データの正式な分類・保存義務の該当性は別途確認する。

## 一律の「7年」にしない

国税庁の一般説明では、個人の青色申告は原則7年で一部書類は5年、白色の事業所得等は法定帳簿7年・その他の帳簿/書類5年という区分がある。法人は原則、申告期限の翌日から7年で、一定の欠損等では10年となる。業務に係る雑所得の保存義務も条件が異なる。

これらは本人への適用を確定した説明ではない。「個人開発だから白色」「青色の選択だけで申告要件を満たす」「取引日から全データ7年」等の扱いをしない。保存対象・期間・起算日は、採る申告方法等が分かった後に確認する。Stripe側の保持も、運営者自身の義務や削除方針と同一ではない。

## 実売上の前に準備するもの（運用案）

1. 運営者だけが扱える非公開の保管先を決める。チャット・GitHub・公開サイト・共有の問い合わせグループに決済原資料を置かない。会計ソフト等の既存保管先の有無も確認する。
2. 本番とテストを分け、Stripeの売上・返金・手数料・入金の記録と原資料を取り出せることを確認する。今回はテスト/本番とも顧客別資料を取得していない。
3. 取引日時・金額/通貨・照合用の取引参照・必要な取引先情報等で照合できる索引を用意する。必要な項目を確認し、顧客情報を過剰に複製しない。カード番号やセキュリティコードを保存しない。
4. CSV等の集計と、授受した請求書/領収書等の電子データを区別して保存する。電子取引の保存義務がある場合は、改ざん防止・検索/閲覧等の適用要件も確認する。印刷やCSV集計だけで原データの保存を置き換えたと判断しない。
5. 売上総額、返金、手数料、調整、実際の銀行入金を突合し、未入金・返金処理中を区別する。会計上の計上時期・処理をこの文書で決めない。
6. 元データを勝手に上書きせず、訂正や再出力の履歴と復元手段を用意する。保存期限は分類・根拠・起算日を付けた台帳で管理し、必要がなくなった情報の削除手順も設計する。

Stripeのレポートは会計資料の準備に使えるが、レポートをダウンロードしただけで電子帳簿保存法等への対応が完了するとは扱わない。月次確認の頻度・担当・保管先・バックアップ方法は運営者と具体化する。

## アプリ記録の削除で壊してはいけないこと

- `charge.refunded` は失効マーカーと対象権利を更新する。失効マーカーを消すと、遅れて届く支払完了イベントとの整合を壊し得る。学習記録削除に混ぜない。
- 月額の自動更新停止、Stripe顧客削除、認証ユーザー削除、クラウド学習記録削除は別操作。税務記録を残すことを理由に、すべての学習記録や問い合わせを一律に残さない。
- 購入予約は期限だけで破棄しない実装。保持期限を追加するときは、既存の重複購入/遅延通知のテストと整合させる。
- テストデータは実売上帳簿と区別する。今回、既存テストデータの消去や本番へのコピーは行わない。

根拠：`functions/index.js` の `createCheckout` / `saveGrant` / `revokeCharge`、`functions/billingEnvironment.js`、`functions/billingPolicy.js`。

## プライバシー掲載文の補足候補

> 学習記録の削除とは別に、決済・請求・返金・法令対応等のため必要な記録を、目的と適用法令に応じて必要な期間保存します。保存が必要な情報とその理由は区別し、不要となった情報は削除対応します。

候補文だけで詳細な保存台帳や適用確認が不要になるわけではない。現時点では数値を仮置きしない。申告方法の決定待ちであっても、原資料の保管準備や他の公開準備は進められる。
