# 問い合わせ履歴の保存・削除手順案

2026-10-22。対象は公開サポート窓口に届く問い合わせ。**文書上の手順整備のみ。メール/投稿/添付の削除、設定変更、送信、定期実行の作成は行っていない。** 通常返信の個人差出人対策は本人指示による保留を維持する。

## 採用済みの保存方針

- 通常問い合わせは対応完了後の再問い合わせ用に最長1年保存。不要になったものは早めに削除する。
- 未解決の請求・紛争、法令上保存が必要な記録は通常問い合わせと区別する。
- 保存の必要性は6か月ごとに点検するが、削除期限の管理は別。次の6か月点検を待って1年を超過させない。
- 学習記録の本人確認後30日以内目標の削除対応、アカウント削除、解約/返金は別手順。

## 1. 受付から対応完了まで

1. 運営者だけが扱う非公開の管理場所に、案件の参照・種別・受付日・状態を記録する。公開Gitやチャットに実案件の氏名/メール/本文/添付を転記しない。
2. 対応中/通常対応完了/保存例外に分類する。完了日と通常の削除上限日を記録し、期限前に処理できる確認方法を用意する。
3. 完了日は実際に対応を終えた日とする。保存期間を延ばすためだけに、古い会話全体を再度「完了」にしない。関連する新規相談は参照関係を残して別に扱う。
4. 未解決請求/紛争等を例外として残す場合は、必要な部分・理由・次の確認日を記録する。完了後も会話全体を理由なく無期限保持しない。

## 2. 削除前に探す場所

| 保管場所 | 確認対象 |
|---|---|
| Google Groups | 対象の会話と各メッセージ、返信・引用・添付 |
| 運営者/担当者のメール | 受信/送信/アーカイブ/ごみ箱、ダイジェストや要約に含まれる対象内容 |
| 転送先・別メールアプリ | 自動/手動転送、端末のローカル保存、メールアプリの同期済み/オフラインの写し |
| ファイル類 | ダウンロードした画像/PDF、保存済みメール、書き出し、調査用メモ、クラウド同期やバックアップ |

グループ履歴を消しても、メンバーへ配信済みのメールが一括で消えるとは扱わない。上記の場所が実際に使われているかは未確認。存在しない保管先を作って複製を増やさない。

運営側が管理する写しと、問い合わせ本人/第三者側の受信メールは区別する。運営の管理外まで回収・即時消去を保証しない。バックアップが直ちに消せない場合は、用途・アクセス制限・反映期限・復元時の再削除を確認し、未確認を「削除完了」にしない。

## 3. 対象限定の削除手順（実行には別途確認が必要）

1. 対象案件と削除理由・範囲を特定。本人からの請求なら必要な確認を行う。定期的な保存期限管理は本人請求とは分ける。
2. 未解決の請求/紛争・法定保存対象が混ざっていないか確認する。残す必要がある場合は最小限を区別し、理由を記録。税務保存の未確定期間を一律1年で削除しない。
3. 対象一覧を運営者が確認し、削除の承認を得る。実際の本文や個人情報を公開チャットへ貼って承認を取る必要はない。グループ全体、受信箱全体、ごみ箱全体の削除は行わない。
4. Google Groupsは対象メッセージを開き、対象のメニューから削除する。削除権限と確認画面を確かめる。会話単位の操作で無関係の相談が消える場合は中断する。
5. 運営側の受信/送信/転送等の写しも対象を再確認して削除する。Gmailではアーカイブは削除ではなく、通常の削除はごみ箱移動。ごみ箱に移すだけで削除完了とせず、最長1年の上限までに対象のごみ箱も確認して完全削除する手順を用意する。30日の自動削除待ちで上限を超えない。ごみ箱全体を空にしない。
6. ダイジェスト、引用、添付、端末保存、バックアップも確認する。複数案件を含むファイルでは、残す必要のある他案件の情報を保護し、対象部分の処理方法を決める。独断で全ファイルを消さない。
7. グループ・各メール・ファイルを再確認し、対象ごとに完了/保留理由を記録する。管理画面から消えたこととサービス提供者の内部バックアップ等の消去を区別し、すべて即時消去したとは案内しない。
8. 本人請求に返信が必要なら、確認できた削除範囲と残す情報/理由を伝える。返信自体にも不要な元本文を引用しない。送信は対象と本文を確認して許可を得る。

## 4. 管理票のひな形（実案件をGitに入れない）

以下の項目を、運営者だけの非公開の場所へ必要最小限で記録する。メール本文・添付をこの管理票へ丸ごとコピーしない。

| 項目 | 記録する内容 |
|---|---|
| 案件参照/種別/状態 | メールを照合できる参照、通常/請求・紛争等、対応中/完了/削除確認中 |
| 日付 | 受付日、完了日、通常削除上限日、期限前の次回確認日 |
| 保存例外 | 必要な範囲・理由・適用確認・次の見直し日。なければ「なし」 |
| 対象一覧 | Groups、受信/送信/転送、添付、端末/バックアップ等の実在する場所 |
| 削除確認 | 対象ごとの実施日、担当、確認結果、保留事項 |

削除証跡に本文・氏名・メールを残し続けて、削除した情報を実質的に再保存しない。管理票自体の保持目的と必要な期間も確認し、原履歴と同じく必要性を見直す。単純な一斉自動削除は作らない。

## 5. 実運用開始前の確認

- 実際のメンバー、配信/転送/会話履歴の設定と、各受信箱/端末/バックアップの写しの有無を確認する。今回管理画面を操作したとは扱わない。
- 管理票の保管先、期限前に確認できる方法、削除担当/不在時の対応を決める。手動管理か自動通知かは未確定で、定期処理は未作成。
- 個人情報のない専用の模擬案件で、受付→完了日管理→対象特定→削除承認→削除→写しの確認まで一括試験する。試験用のメール送信/投稿/削除も実行前に対象と影響を示して承認を得る。
- 個人差出人対策、販売者情報の開示試験、学習記録の削除試験と混同しない。
